# omp-subagent-ng

[中文](README.zh-CN.md)

- **Conversation forks (`fork_task`)**
  - `fork_task` tool — Does: dispatches native `task` children that continue a copied conversation under the source's exact system prompt, tools and message prefix, so forks of one source share the provider's cached prefix. When: when the model calls `fork_task` (a top-level tool, `loadMode: "essential"`); needs `async.enabled: true` and a persisted session. Example: `fork_task({ context: "…", tasks: [{ task: "Write tests for src/auth", name: "Tests", workspace: "isolated_from_caller" }] })` returns the child id `Tests`, or `Tests-2` when an earlier agent of the session holds `Tests`.
  - `from` source — Does: forks another registered agent's conversation (live, idle or parked) instead of the caller's; a parked source is forked from the request it kept at park without waking it. When: when an item sets `from`. Example: `{ from: "ReadmeConfig", task: "…" }`.
  - `agent` role binding — Does: gives the child that agent's model binding (`task.agentModelOverrides`, else the definition's `model`), its definition prompt as a `<role agent="…">` block at the head of the assignment, and its `output` as the child's `yield` schema when the item sets no `outputSchema`, while keeping the source's tools. When: when an item sets `agent`. Example: `{ agent: "reviewer", task: "…" }` puts `<role agent="reviewer">…</role>` before the shared `context`.
  - `effort` mapping — Does: maps `lo`/`med`/`hi` onto the target model's own thinking range (lowest, middle, highest supported level). When: when an item sets `effort`; no effect while `task.enableEffort` is false. Example: `{ effort: "hi", task: "…" }`.
  - `shake` elision — Does: runs the same `session.shake("elide")` as `/shake` on the inherited transcript, keeping the newest tokens and `skill://`/`local://PLAN.md` reads, and appends the summary to the tool result. When: at staging, when an item sets `shake: true`. Example: the result ends with `[fork_task] <name>: <shake summary>`.
  - `outputSchema` / `schemaMode` — Does: passes a JSON Schema object and its enforcement mode to the child's `yield`; without it the child takes the bound role's `output`, else `fork:self`'s `{report: string}`. While `task.structured` is off the host ignores both and the child takes `{report: string}`. When: at dispatch. Example: `outputSchema: { type: "object", properties: { report: { type: "string" } }, required: ["report"] }`.
  - Depth and prerequisite guard — Does: refuses before staging when the caller's `taskDepth` + 1 reaches `task.maxRecursionDepth`, when `task` is unavailable, or without background jobs. When: at the start of every `fork_task` call. Example: ``fork_task: requires background jobs (`async.enabled: true`).``
- **What a fork child sees**
  - `fork:self` agent — Does: the internal agent definition every fork child is dispatched as; its prompt and tools are replaced by the source's and its model is pinned. When: on every `fork_task` dispatch; never named in `task` calls. Example: `agents/fork-self.md`, `name: fork:self`, `structured: true`, `output` `{report: string}`.
  - Fork notice — Does: appends a `<system-notice cause="fork_task">` after the copied conversation stating that the history is background only, the job is the following assignment, runtime verification is required before handoff, the result is delivered with `yield`, and whether the child shares the parent's working directory or runs in an isolated copy. When: written into the staged child transcript before the child's first turn. Example: `Above: the conversation of the parent agent that spawned you, copied as background. You continue under its system prompt and tools.`
  - Staging into the artifact store — Does: stages the conversation in the calling session's artifacts directory and moves it, under the spawn key the host allocated, to where the executor opens the child, refusing to overwrite an existing transcript. When: on the host's `before_subagent_spawn` hook for `task` invocations. Example: block reason `fork_task: <path>.jsonl already exists; refusing to overwrite it.`
  - Request replication — Does: sends every child request with the source's captured system prompt, tool declaration and message prefix, never appending the child's own tools; a source tool the child has no registration for leaves the child running; a call to it does not run, and OMP answers `Tool <name> not found`. A missing snapshot blocks the child before any model call instead of running a different contract. When: on `before_agent_start` of the child session. Example: `the fork's request snapshot is no longer available; create a fresh fork from the parent`.
  - Own-`yield` delta — Does: tells every fork child that its result goes through its registered `yield`, called directly as a function call of its own, whether or not the copied declaration lists `yield`, followed by that tool's description and JSON Schema. When: as a context delta on `before_agent_start`, and again after a tool batch on `tool_result` when compaction dropped it. Example: ``Emit it as a function call of its own, exactly like a call to `read` or `bash`: name `yield`, arguments `{"data": <your result>}` ``.
  - Difference reminder — Does: tells a fork child how its session differs from the request it continues: the working directory the copied conversation ran in against its own, with the repository roots whose relative paths correspond, declared tools it has no registration for (and that calls to them do not run), tools reported unavailable earlier that are registered now, and context files under its working directory that are missing from, new to, or changed against the source's system prompt, with the current content, or found at another path with the same content. Unchanged differences are not sent again, and the reminder is withdrawn when nothing differs. When: as a context delta on `before_agent_start` and after a tool batch on `tool_result`. Example: `<system-reminder source="omp-subagent-ng/fork-diff">` listing ``- `session_query` ``.
  - Cross-thread source channel — Does: answers requests from other threads of this process for a source's latest request. When: started when the extension loads. Example: `BroadcastChannel("omp-fork-task/source")`.
- **Workspace modes (`workspace`)**
  - Three-state `workspace` — Does: selects `"shared"` (share caller checkout), `"isolated_from_caller"` (new worktree from caller checkout), or `"isolated_from_source"` (new worktree seeded with the `from` agent's uncommitted isolated changes, handed back together with the child's changes). Defaults to `"shared"` without `agent` and `"isolated_from_caller"` with `agent`; plan mode forces `"shared"`. When: checked before dispatch; `isolated_from_source` overlay applied on the child's `before_agent_start`, after its workspace start is recorded and before its first turn. Example: `{ from: "Impl_1a2b", workspace: "isolated_from_source", task: "…" }`.
  - Rejection codes — Does: refuses the whole call before dispatch with a coded reason (`child-not-isolated`, `source-not-isolated`, `source-running`, `source-handed-back`, `nested-repo`, `overlay-conflict`); a late `overlay-conflict` stops the child before its first model call. When: during staging, or at the child's first turn for late conflicts. Example: `workspace "isolated_from_source" rejected (source-running)`.
  - Workspace start records — Does: records each isolated subagent's workspace start so inherited changes can be read later. When: on the first `before_agent_start` of every subagent transcript. Example: `<session artifacts>/fork-task.start.json`.
  - Prepare command — Does: runs the command a flow box's `prepare` left for a subagent in that subagent's workspace, after the inherited changes are applied and before its first turn; a failure or a timeout after 240 s stops the session before any model call. When: on the first `before_agent_start` of the subagent transcript. Example: ``the `prepare` command exited with 1 in this workspace: …``.
- **Topics**
  - `help://fork_task/limits` — Does: lists prerequisites, unsupported fields, source errors, `isolated_from_source` rules and eval `await tool.fork_task(...)` behavior via both native `docTopics: toDocTopics(FORK_TASK_TOPICS)` and `registerToolTopics("omp-subagent-ng", ...)`. When: when the model reads it; the short tool description points to it. Example: ``Not fork fields: `steps`, `solutionSpace`, `model`, `tools`.``
- **Report-limit check**
  - Report-limit judgment — Does: blocks a `fork_task` call when the shared `context` or an item's `task` (items with `agent` `task:*` or omitted) caps the length of the worker's report, asking the model one question per item under a 25 s deadline. When: on every `fork_task` call, after argument normalization and prerequisite checks, before staging. Example: block reason ``禁止限制 task 系列 subagent 的报告字数：… 删掉字数/长度限制后重新派发；报告长时让 worker 写入文件（如 `local://<name>.md`）…``.
  - `@omp-subagent-ng` model role — Does: the model the judgment asks first, then the `default` role chain; no model, a failed request or an unparsable answer lets the call run. When: at each judgment. Example: assign it in `/model` → "+ New role"; the model must answer `report-limit: true` or `report-limit: false`.
  - Verdict cache and log — Does: remembers only `clear` verdicts per process (sha256 of trimmed context and task) and logs one line per judged call. When: after each judgment. Example: log line `omp-subagent-ng report-limit verdicts`.
- **Fork records in session artifacts**
  - Request copy, overlay, prepare command, parked request and workspace start — Does: keeps each record in the artifacts directory of the session it belongs to, so it lives and goes with that session's transcript. When: the request copy, overlay and prepare command at spawn, the parked request when a session parks, the workspace start at a subagent's first turn. Example: `<child artifacts>/fork-task.replica.json`, `fork-task.overlay.patch`, `fork-task.prepare`, `<session artifacts>/fork-task.request.json`, `fork-task.start.json`.
  - Shutdown cleanup — Does: removes the staged conversations of a session's undispatched forks. When: on `session_shutdown`. Example: `fork_task: cleaning up the staged conversation failed` is logged on failure.
- **Flows (`flow` tool, skill `omp-subagent-ng`)**
  - `flow` tool — Does: keeps one flow of boxes per session in an append-only log beside the session (`<session>/flow.jsonl`), starts every item whose inputs have values from one background job, wakes the main session once when the flow comes to rest or stops, and answers every call with the store's verdict: headline, what holds the flow back, the `next:` operations open now, and one line per change. When: the model calls `flow` with `op` `define`, `supply`, `run`, `stop`, `status`, `value`, `retract`, `keep`, `retry`, `answer`, `agree` or `disagree` (`loadMode: "essential"`); `define` also takes the optional boolean `noEscape`; `run` needs `async.enabled: true` and a persisted session. Example: `{ op: "supply", name: "issue", value: "\"#12\"" }`.
  - Boxes and wiring — Does: an agent box starts one fresh subagent session per item with `schemaMode: "strict"`; a command box runs one POSIX command per item, inputs quoted as one shell word each. `input.<name>` reads a supplied value, `<box>` or `<box>.<field>` a result, `<box>[]` or `<box>.<field>[]` fans out one item per element, `<box>!<type>` takes each raise of that type and answers it, one raise port per box and never beside a `[]`. Several `[]` inputs pair by leaf path; a path only some of them reach is reported `unpaired` and keeps the flow from completing. Definitions are plain JSON, checked whole at `define`, and replace one box at a time. When: at `define`; references are resolved while the flow runs. Example: `work: { agent: "flow:worker", model: "task:low", brief: "…{{slice}}", in: { slice: "scout.slices[]" }, out: {…}, raises: ["question"], isolated: true }`.
  - Checks — Does: a box with `checks` names one agent box or a non-empty array of them. A command check reopens every checked item at its path in a new session when it exits with a code in `rejects` (`[1]` when absent); an agent check does so by yielding `{"status": "reject", "feedback": "…"}`. Each reopened session gets its own handoff, the check's output or feedback, and the values the check was given that round; everything computed from the rejected results is dropped. Any other non-zero exit is the `exit` exception. Reopenings count towards each checked box's `bound`; when any checked item is in its last allowed session, nothing reopens and the check fails `bound_exceeded`, which stops the flow. When: when the check settles. Example: `{ command: "tsc --noEmit", in: { work: "work[]" }, checks: "work", rejects: [1, 2] }`.
  - Ruling what a session raises — Does: a box taking `<worker>!question` rules on the raise inside the flow, and the worker continues with the ruling; it may send the worker back to probe while sessions remain, or, when its own schema offers an outward raise such as `ask_user`, rest the flow at the ruling item until `answer`. Under `noEscape` it decides every point itself. When: when a worker raises. Example: `{ agent: "flow:adjudicator", model: "task:high", brief: "Rule on {{raised}}", in: { raised: "work!question" }, out: { type: "object" }, raises: ["ask_user"] }`.
  - Split requests — Does: a session of a box with `splits` (which needs exactly one `[]` input and `isolated: true`) asks the flow's author for a split with its `flow_split` tool, giving the parts and the details to judge them; the call blocks until the author answers with `flow` op `agree`, or op `disagree` and a `reason`. The author is woken with a message naming the item, the session, the details and the parts, and `status` lists the request as `split asked` while it waits. On disagree the tool returns the reason and the session goes on. Under `noEscape` a request that passes its checks is approved at once without a message. When: `flow_split` is active only in flow sessions that may still split; the message is delivered when the request arrives. Example: ``Answer with the `flow` tool: op `agree` with keys ["work#0"], or op `disagree` with keys ["work#0"] and a `reason`.``
  - Splitting — Does: after the author agrees, the session yields `{status: "split", handoff}` and the approved parts replace the item's element as new items of the same box (`work#0` → `work#0.0`, `work#0.1`). Each part's first session is a fork of the splitting session (`fork_task` with `from`, `workspace: "isolated_from_caller"`, no shake): it keeps that conversation, starts in its own worktree from the changes the splitting session handed back, and may split again while `splits` allows. No session joins the parts: `work[]` fans out over the leaves by their paths and `work` is the array of the leaves' results, so a reducing box is an ordinary box taking `work`. Each leaf is checked, reopened and retracted on its own. When: when a split settles. Example: `~ work#0: split in session 1 into 2 parts, work#0.0, work#0.1`.
  - Sessions and hand-over — Does: every firing but a part's first is a new session; each yields `{status, value | raise, detail, handoff: {did, decided, unverified}}`, or `{status: "reject", feedback}` when its box `checks` another; a later session of the same item gets the earlier handoff with the answer or the check output and the values the check was given, the item's notes file, and, for `isolated: true`, the changes the earlier session left, whatever model it runs on. A session that yields while OMP keeps its changes on `omp/task/<id>` instead of merging them fails with `workspace`. When: at each firing and when a session ends. Example: `<session>/flow-boards/work%230.md`.
  - Exceptions, stops and stale values — Does: `spawn`, `workspace`, `session`, `schema`, `protocol`, `bound_exceeded`, `exit`, `timeout` and `host` fire the item again as often as the box's `handle` allows, then stop the whole flow; `run` is refused until each failed item is redefined, retracted or retried, and while results produced under a changed box, agent prompt or model setting are neither kept nor retracted. When: when an item settles; at `run`. Example: `next: retry or retract scout, or define scout again`.
  - `noEscape` — Does: keeps everything inside the flow: `run` is refused until every input a box takes is supplied, a raise type no box answers is not offered to sessions, a split request that passes its checks is approved without asking you, and `session`, `timeout`, `protocol` and `schema` failures fire once more when the box's `handle` does not name them. When: set by `flow` op `define`'s `noEscape`, or a helper spec's; omitted keeps the current value, and a call that only changes it is applied. Example: `{ op: "define", boxes: "{}", noEscape: true }`.
  - Role agents — Does: `flow:scout`, `flow:worker`, `flow:adjudicator`, `flow:guardian` and `flow:verifier` bring their own system prompts and no model; a box's `model` names the tier whose model setting they run on. When: when a box names them in `agent`. Example: `agents/flow-worker.md`.
  - `flow.js` helper — Does: defines `flow.define(boxes, opts)` (`opts.noEscape`), `supply`, `run`, `stop`, `status`, `retract`, `keep`, `retry`, `answer`, `agree` and `disagree`, which take JavaScript values, print the verdict and throw when the call is refused; `flow.use(spec, opts)` defines a `{ boxes, inputs?, noEscape? }` spec or a plain boxes map and supplies its inputs; `flow.presets.swarm(options, ...workers)` and `flow.presets.loop(options, ...agents)` return such specs; `flow.value(key)` returns a stored value. When: after a JS cell runs `%load skill://omp-subagent-ng/flow.js`. Example: `await flow.use(flow.presets.loop({ over: "input.items[]", check: { agent: "flow:guardian", brief: "…", out: { type: "object" } } }, { name: "red", brief: "…" }));`.
  - Eval subagent guard — Does: refuses, before it runs, an `eval` cell whose source calls the eval prelude's `agent()` or `workpool()` (Python or JS, also `globalThis.agent(…)` in JS), naming the function and pointing to `help://flow/eval`; a script the cell runs with `%load` (a standalone `%load <script>` cell, or a `%load` line in Python, followed through nested loads) counts as the cell's source, and IPython magic and shell lines are skipped except for the Python that `%time`/`%timeit` and `%%capture`/`%%timeit` run; the source is parsed, so names in strings, comments, members and keyword arguments do not count, and a function reached at runtime (`globals()["agent"]`, `eval()`) is not caught. `tool.flow`, `tool.task`, `tool.fork_task`, `wait`, `judge`, `judgeBatch` and `completion` are not affected. When: on every `eval` `tool_call`, in the main session and in subagent sessions. Example: ``This eval cell was not run: it calls `agent()` from the eval prelude. … start them through the flow tool instead:`` followed by `help://flow/eval`.
  - `help://flow/boxes`, `help://flow/lifecycle`, `help://flow/eval` — Does: document the box fields, references, checks, rulings, sessions and exceptions; running, stopping, resuming, stale values, raises, split requests and `noEscape`; and the eval helper. When: when the model reads them; the tool description lists them. Example: `| \`rejects\` | command | With \`checks\`: the exit codes that reject the checked result, \`[1]\` when absent. … |`.
