# omp-subagent-more

[中文](README.zh-CN.md)

- **Conversation forks (`fork_task`)**
  - `fork_task` tool — Does: dispatches native `task` children that continue a copied conversation under the source's exact system prompt, tools and message prefix, so forks of one source share the provider's cached prefix. When: when the model calls `fork_task` (a top-level tool, `loadMode: "essential"`); needs `async.enabled: true` and a persisted session. Example: `fork_task({ context: "…", tasks: [{ task: "Write tests for src/auth", name: "Tests", isolated: true }] })` returns the child id `Tests`, or `Tests-2` when an earlier agent of the session holds `Tests`.
  - `from` source — Does: forks another registered agent's conversation (live, idle or parked) instead of the caller's; a parked source is forked from the request it kept at park without waking it. When: when an item sets `from`. Example: `{ from: "ReadmeConfig", task: "…" }`.
  - `agent` role binding — Does: gives the child that agent's model binding (`task.agentModelOverrides`, else the definition's `model`), its definition prompt as a `<role agent="…">` block at the head of the assignment, and its `output` as the child's `yield` schema when the item sets no `outputSchema`, while keeping the source's tools. When: when an item sets `agent`. Example: `{ agent: "reviewer", task: "…" }` puts `<role agent="reviewer">…</role>` before the shared `context`.
  - `effort` mapping — Does: maps `lo`/`med`/`hi` onto the target model's own thinking range (lowest, middle, highest supported level). When: when an item sets `effort`; no effect while `task.enableEffort` is false. Example: `{ effort: "hi", task: "…" }`.
  - `shake` elision — Does: runs the same `session.shake("elide")` as `/shake` on the inherited transcript, keeping the newest tokens and `skill://`/`local://PLAN.md` reads, and appends the summary to the tool result. When: at staging, when an item sets `shake: true`. Example: the result ends with `[fork_task] <name>: <shake summary>`.
  - `outputSchema` / `schemaMode` — Does: passes a JSON Schema (given as JSON text) and its enforcement mode to the child's `yield`; without it the child takes the bound role's `output`, else `fork:self`'s `{report: string}`. While `task.structured` is off the host ignores both and the child takes `{report: string}`. Invalid JSON refuses the whole call before staging. When: at dispatch. Example: `outputSchema: '{"type":"object","properties":{"report":{"type":"string"}},"required":["report"]}'`, error `tasks[0].outputSchema is not valid JSON: …`.
  - Depth and prerequisite guard — Does: refuses before staging when the caller's `taskDepth` + 1 reaches `task.maxRecursionDepth`, when `task` is unavailable, or without background jobs. When: at the start of every `fork_task` call. Example: ``fork_task: requires background jobs (`async.enabled: true`).``
- **What a fork child sees**
  - `fork:self` agent — Does: the internal agent definition every fork child is dispatched as; its prompt and tools are replaced by the source's and its model is pinned. When: on every `fork_task` dispatch; never named in `task` calls. Example: `agents/fork-self.md`, `name: fork:self`, `structured: true`, `output` `{report: string}`.
  - Fork notice — Does: appends a `<system-notice cause="fork_task">` after the copied conversation stating that the history is background only, the job is the following assignment, runtime verification is required before handoff, the result is delivered with `yield`, and where the child's workspace is. When: written into the staged child transcript before the child's first turn. Example: `Above: the conversation of the parent agent that spawned you, copied as background. You continue under its system prompt and tools.`
  - Staging into the artifact store — Does: stages the conversation in the calling session's artifacts directory and moves it, under the spawn key the host allocated, to where the executor opens the child, refusing to overwrite an existing transcript. When: on the host's `before_subagent_spawn` hook for `task` invocations. Example: block reason `fork_task: <path>.jsonl already exists; refusing to overwrite it.`
  - Request replication — Does: sends every child request with the source's captured system prompt, tool declaration and message prefix, never appending the child's own tools; a source tool the child has no registration for leaves the child running and is blocked when called. A missing snapshot blocks the child before any model call instead of running a different contract. When: on `before_agent_start` of the child session. Example: `the fork's request snapshot is no longer available; create a fresh fork from the parent`.
  - Own-`yield` delta — Does: tells every fork child that its result goes through its registered `yield`, called directly as a function call of its own, whether or not the copied declaration lists `yield`, followed by that tool's description and JSON Schema. When: as a context delta on `before_agent_start`, and again after a tool batch on `tool_result` when compaction dropped it. Example: ``Emit it as a function call of its own, exactly like a call to `read` or `bash`: name `yield`, arguments `{"data": <your result>}` ``.
  - Difference reminder — Does: tells a fork child how its session differs from the request it continues: declared tools it has no registration for (and that calls to them are blocked), tools reported unavailable earlier that are registered now, and context files under its working directory that are missing from, new to, or changed against the source's system prompt, with the current content. Unchanged differences are not sent again, and the reminder is withdrawn when nothing differs. When: as a context delta on `before_agent_start` and after a tool batch on `tool_result`. Example: `<system-reminder source="omp-subagent-more/fork-diff">` listing ``- `session_query` ``.
  - Unavailable-tool block — Does: blocks a call to a tool the copied declaration names but the child has no registration for, before it runs. When: on `tool_call` in a fork child. Example: block reason ``fork_task: `session_query` is declared to you because your tool declaration stays identical to the parent's request, but not registered in this session; this call did not run.``
  - Cross-thread source channel — Does: answers requests from other threads of this process for a source's latest request. When: started when the extension loads. Example: `BroadcastChannel("omp-fork-task/source")`.
- **Workspace inheritance (`workspace: "source"`)**
  - Source overlay — Does: applies the uncommitted changes the `from` agent made in its own isolated workspace to the child's isolated copy, handed back together with the child's changes. When: checked before dispatch; applied on the child's `before_agent_start`, after its workspace start is recorded and before its first turn. Example: `{ from: "Impl_1a2b", workspace: "source", task: "…" }`.
  - Rejection codes — Does: refuses the whole call before dispatch with a coded reason (`child-not-isolated`, `source-not-isolated`, `source-running`, `source-handed-back`, `nested-repo`, `overlay-conflict`); a late `overlay-conflict` stops the child before its first model call. When: during staging, or at the child's first turn for late conflicts. Example: `workspace "source" rejected (source-running)`.
  - Workspace start records — Does: records each isolated subagent's workspace start so inherited changes can be read later. When: on the first `before_agent_start` of every subagent transcript. Example: `<session artifacts>/fork-task.start.json`.
- **Topics**
  - `xd://fork_task/limits` — Does: lists prerequisites, unsupported fields, source errors and the `workspace "source"` rejection table. When: when the model reads it; the description's last lines point to it. Example: ``Not fork fields: `steps`, `solutionSpace`, `model`, `tools`.``
  - `xd://fork_task/batch` — Does: explains templated fork batches from eval. When: when the model reads it. Example: `await tool.fork_task(...)` from an eval cell; results arrive in the conversation, not in the cell.
- **Report-limit check**
  - Report-limit judgment — Does: blocks a `fork_task` call when the shared `context` or an item's `task` (items with `agent` `task:*` or omitted) caps the length of the worker's report, asking the model one question per item under a 25 s deadline. When: on every `fork_task` `tool_call`, before it runs. Example: block reason ``禁止限制 task 系列 subagent 的报告字数：… 删掉字数/长度限制后重新派发；报告长时让 worker 写入文件（如 `local://<name>.md`）…``.
  - `@omp-subagent-more` model role — Does: the model the judgment asks first, then the `default` role chain; no model, a failed request or an unparsable answer lets the call run. When: at each judgment. Example: assign it in `/model` → "+ New role"; the model must answer `report-limit: true` or `report-limit: false`.
  - Verdict cache and log — Does: remembers only `clear` verdicts per process (sha256 of trimmed context and task) and logs one line per judged call. When: after each judgment. Example: log line `omp-subagent-more report-limit verdicts`.
- **Fork records in session artifacts**
  - Request copy, overlay, parked request and workspace start — Does: keeps each record in the artifacts directory of the session it belongs to, so it lives and goes with that session's transcript. When: the request copy and overlay at spawn, the parked request when a session parks, the workspace start at a subagent's first turn. Example: `<child artifacts>/fork-task.replica.json`, `fork-task.overlay.patch`, `<session artifacts>/fork-task.request.json`, `fork-task.start.json`.
  - Shutdown cleanup — Does: removes the staged conversations of a session's undispatched forks. When: on `session_shutdown`. Example: `fork_task: cleaning up the staged conversation failed` is logged on failure.
- **Eval orchestration (skill `omp-subagent-more`)**
  - `orchestrate(spec)` — Does: runs items made of subagent stages, each stage one `agent()` call checked against its `data` JSON Schema with `schemaMode: "strict"`; items do not wait for each other. When: after a JS cell runs `%load skill://omp-subagent-more/orchestrate.js`. Example: `const run = orchestrate({ items: [{ id: "auth", stages: [{ task: "Read src/auth…", data: {…} }] }] })`.
  - `run.drive()` / `run.status()` — Does: advances every item and returns `{ done, failed, needs_input, running }` when all settle or a new question appears; `status()` returns the view without advancing. When: called by the orchestrating cell, again after a background-result wake-up. Example: `const view = await run.drive();`.
  - `needs_input` protocol and `run.answer()` — Does: a stage yields `{"kind": "needs_input", "question": "…", "options": […]}` for an open decision, and `answer(id, text)` sends the reply to the same subagent. When: when a stage reaches a decision the assignment leaves open. Example: `await run.answer("auth", "Keep the old API.");`.
